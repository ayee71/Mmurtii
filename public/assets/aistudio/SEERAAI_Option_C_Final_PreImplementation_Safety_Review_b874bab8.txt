TASK 3 — FIX THE 64 KB MEANING
The prior proposal used `String.size() <= 65536` but described the limit as 65536 BYTES.
Firebase Security Rules `String.size()` returns the number of characters, not UTF-8 bytes. `String.toUtf8()` returns bytes; `Bytes.size()` returns the number of bytes.
Verify this using official Firebase Rules references.
Determine whether the product contract intends:
A. 65,536 characters, or
B. 65,536 UTF-8 bytes.
The reported dataUrl is typically an ASCII/base64 string, where characters equal bytes, but the rules do not appear to enforce ASCII/base64 unless an existing rule does.
Do not silently change the current contract. Recommend byte-count validation using `.toUtf8().size()` if the stated policy is truly bytes; add a multibyte UTF-8 regression test. Otherwise explicitly rename the limit as characters.
Preserve optional behavior: field absent and explicit null should be accepted only if consistent with current schema; non-string values denied; valid strings at the inclusive limit accepted; above-limit denied.
